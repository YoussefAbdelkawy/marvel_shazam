Architecture · build + evaluation

Building the index, and keeping score honestly

The offline side: how the index is built from subtitle files, and how the frozen benchmark measures every change and feeds both the fine-tune and the tuned settings back into search.

No data leaks

Three walls between train and test

  • Each title is cut by position: 80% train, 10% dev, 10% test
  • Fine-tuning pairs come only from train; tuning uses only dev
  • Test ran once, at the very end

The benchmark

2,400 dev + 2,400 test queries

  • Random windows of 10/20/40 words, never chunk-aligned
  • Each in a clean and a Whisper-style noisy version
  • 600 non-Marvel lines (Cornell movies) per split

No notebooks

Plain scripts

Every step is a .py file you can re-run; results land in eval/ and RESULTS.md.
